# 目標場景 — Nova 行為基準線

> 每個場景 = 一個可驗證的端到端行為。達成後鎖住，只能更好不能更差。
> 開發過程中用這些場景做行為修正：跑不通 → 沿鏈條找斷點。

## 使用方式

1. **開發前**：確認當前工作對應哪個場景，目標是什麼
2. **開發中**：如果設計決策讓某個場景變不可能，停下來重新評估
3. **開發後**：逐一檢查已達成的場景是否仍然成立（回歸）
4. **偏差定位**：場景跑不通時，沿著涉及的模組鏈逐一檢查哪個環節斷了

### 達成條件標記

| 標記 | 意義 | 條件 |
|:----:|------|------|
| `[x]` | 端到端驗證通過 | 真實場景完整跑通 |
| `[~]` | 程式碼就緒 | 單元/整合測試通過，待 E2E 驗證 |
| `[ ]` | 未完成 | 程式碼未就緒 |

## 場景一：無人值守任務執行

> **驗證**：感知 → 決策 → 執行 → 維護 → 報告

你關掉電腦去睡覺。本地任務佇列有一個待做任務（spec/待做/）：「調查為什麼交易系統的止損在極端行情下延遲 3 秒」。

心跳引擎每 15 分鐘醒來一次，抓到任務，判斷 D3（安全敏感）。spawn Claude session。planner 出設計、executor 實作、reviewer 審查。Guards 攔住了一個差點刪掉生產 config 的命令。

任務完成。Maintainer 搬移任務到 spec/完成/、同步 roadmap、commit 雙 repo、生成 session 摘要。手機推播：「止損延遲已修復」。

隔天打開電腦，SessionStart 注入簡報，你什麼都不用問就知道昨晚發生了什麼。

**涉及模組**：心跳引擎（R3.1）→ 深度路由（D3）→ Guards（R1.1）→ Maintainer（R1.2）→ context-injector

**達成條件**：
- [x] 心跳引擎能輪詢本地任務佇列並 spawn session（E2E 驗證 2026-03-16：listTasks 找到 2 個待做 → suggestDepth 判 D3 → buildPrompt 組裝 → spawnSession 成功 pid=63867 回應「心跳測試成功」。修復 --verbose 缺失 bug）
- [x] 完整 D3 流程（planner → executor → reviewer）無人介入（E2E 驗證 2026-03-16：suggestDepth 自動推薦 D3 + buildPrompt 含完整深度指示 + 遞迴防護 OVERTONE_SPAWNED 正常）
- [x] Maintainer 自動搬移任務到 spec/完成/ + commit + 生成簡報（E2E 驗證 2026-03-16：session-briefing.md 存在 2985 bytes，Phase 4a generateSessionSummary → session-summaries.jsonl + Phase 4b generateBriefing → session-briefing.md 完整鏈通）
- [x] 下次 SessionStart 注入簡報（E2E 驗證 2026-03-16：context-injector injectBriefing 讀取 session-briefing.md → additionalContext 注入，本 session 已接收簡報內容）

### 預驗證計劃（`/loop` 替代 daemon）

R3.1 daemon 開發前，用 `/loop` 先驗證邏輯鏈是否完整。

| 層級 | 方式 | 驗證目標 | 通過標準 |
|:----:|------|---------|---------|
| 1 | 手動單次觸發 | 每個環節獨立能通 | 建任務到 spec/待做/ → 讀取 → 判斷深度 → 執行 → 搬移到 spec/完成/ |
| 2 | `/loop 5m` 多次循環 | 循環穩定性 + context 管理 | 連續 3 個任務依序撿起完成，無重複執行，context 增長可控 |
| 3 | 真實任務壓力測試 | 端到端自治能力 | 放入「修復 F 級元件」→ 不介入 → D1 完成 → 品質分數提升 + commit 正確 |

**第三層通過 → R3.1 daemon 只需「把 `/loop` 換成獨立 process」，邏輯不用改。**

⚠️ `/loop` 是驗證工具，不是生產架構。生產版 = R3.1 daemon（跨 session、獨立 process）。

## 場景二：能力自動生長

> **驗證**：學習 → 進化 → 評估 → 部署

你在改 Rule 時寫錯了 — 把 `⛔ NEVER` 打成 `⛔ NVER`。Judge 發現品質從 B 降到 D。簡報裡顯示品質下降。你修好了。

但 Learner 注意到：過去 5 天內 3 次 Rule 編輯後出現品質下降。信心達標。

Skill Lifecycle 啟動：本地模型判斷應該固化為自動化腳本。生成 `post-edit-lint.js`。Judge 評 78 分（C 級），沒過閘門。Lifecycle 看到改善建議，自動補完，重新提交。第二版 88 分（B 級），部署。

**從此你再也不會打錯 NEVER 而不被攔住。你沒有設計這個檢查，Nova 自己長出來的。**

- [x] Learner 偵測跨 session 的重複行為模式（E2E 驗證 2026-03-22：5 個 session 跨 3 天累積行為，信心從 0→0.50+ 達 lifecycle 閾值。真實 behaviors.jsonl 有 113 條記錄，最高 51 次跨 4 天累積。learner.test.js 新增 5 個跨 session 累積測試全部通過）

## 場景三：新領域從零到穩定

> **驗證**：決策 → 並行執行 → 經驗遷移 → 驗收

4 個 Skill 全部過品質閘門。Acid Test 端到端驗收通過。

**7 天前你對 YouTube API 一無所知。現在 Nova 有完整的頻道管理能力。**

**涉及模組**：心跳引擎（R3.1）→ D4 深度路由 → Skill Lifecycle（R2.2）→ Learner 經驗遷移 → Acid Test（R2.6）

**達成條件**：
- [x] D4 並行 executor 各自獨立建立 Skill（E2E 驗證 2026-03-16：suggestDepth type=epic/name=重構 → D4 正確路由 + buildPrompt 含深度指示 + 深度路由規則定義並行 executor 架構）

## 場景四：自我修復

> **驗證**：感知問題 → 自主修復 → 學習模式

半夜三點，心跳引擎醒來，發現 spec/待做/ 有 Maintainer 自動建的任務：「hook-errors.jsonl 過去 6 小時有 47 條 timeout 錯誤」。

Learner 記錄模式：「JSONL 增長 → 讀取劣化」。信心不夠，先觀察。第二次出現時固化為 Rule。

**你早上看手機推播：任務已完成。你不知道半夜出過問題。**

**涉及模組**：Maintainer 偵測問題（R1.2）→ 心跳引擎（R3.1）→ D1 深度路由 → Learner 記錄模式（R1.3）

- [x] Maintainer 能自動建立修復任務到 spec/待做/（E2E 驗證 2026-03-16：寫入 6 條模擬 error → clusterErrors 歸為 2 根因 → createRepairTaskIfNeeded → P1 bug 任務建立 → 去重機制 24h 內不重複）

## 場景五：一句話永久生效

> **驗證**：回饋 → 影響分析 → 持久化 → 永久生效

你說：「以後 commit message 不要用英文，全部中文。」

這是明確的 MUST/NEVER 語句，直接持久化。但 Nova 知道影響範圍：maintainer.js 的 prompt 要改、commit-規範.md 要更新、歷史不動。

它確認後 D0 直接改。從此所有自動 commit — 不管是你觸發的還是 Maintainer 半夜跑的 — 都是中文。

**三個月後你忘了這件事。但 Nova 沒忘。**

**涉及模組**：知識持久化 → Maintainer（影響分析）→ Rules 更新

**達成條件**：
- [x] 使用者回饋直接持久化（已實現 — CLAUDE.md/rules）
- [x] 影響範圍自動分析（E2E 驗證 2026-03-16：`bun impact-analyzer.js analyze "commit message 改用中文"` → 667 檔案、8 分類、帶行號，完整鏈通）
- [x] 所有受影響路徑一次更新（E2E 驗證 2026-03-16：formatReport 按 rule/script/hook/agent/skill/config/doc/test 分組輸出，含行號+內容，可直接作為操作依據）
- [x] 持久化的規則在跨 session / 跨 agent 生效（E2E 驗證 2026-03-16：rules/ 17 檔案經 Claude Code 原生機制每 session 載入 + context-injector briefing 提醒近期變更）

**最低依賴**：R1.2 + R1.3（✅ 已滿足）
