# 製作規範 — 章文件

> 最後更新：2026-03-17

## 概述

3 條製作規則定義「每個元件怎麼做才算合格」，與設計原則（CLAUDE.md）互補。

⛔ NEVER 新增元件未通過合規 checklist。📋 MUST 每條規則有可檢驗標準。

## 製作規則

### 1. 完全閉環

📋 MUST 每個流程有回饋路徑。⛔ NEVER 資訊只流出不流回。

**可檢驗標準**：
- 📋 MUST 每個 event$ 事件有至少一個 subscriber 消費
- ⛔ NEVER 空 `catch {}`（至少 log error message）
- 📋 MUST 每個偵測結果有對應行動建議（不只報告問題）

**現有實踐**：
- nova-server event$ → writeFlowEvent + broadcast + metrics.onEvent（3 個 subscriber）
- metrics 異常偵測 → anomaly_detected 事件 → SSE 推送
- `/health` 端點回傳 metrics + anomalies

**對應 rule**：`rules/閉環規範.md`、`CLAUDE.md`（禁止靜默失敗）

### 2. 自動修復

📋 MUST 每個元件定義失敗恢復策略。⛔ NEVER crash 只靠人工修復。

**可檢驗標準**：
- 📋 MUST 每個 handler 有 try-catch 隔離（單點錯誤不傳播）
- 📋 MUST 常駐服務有 auto-start fallback
- 📋 MUST event$ subscriber crash 不影響 dispatch 主流程

**現有實踐**：
- hook-client.js fallback：nova-server 不可用 → import 舊 evaluate()
- hook-client.js auto-start：dispatch 失敗 → 檢查 health → spawn nova-server
- dispatch() handler error → catch 隔離，不影響其他 handler
- event$ subscriber → 各自 try-catch，下游崩潰不影響 pipeline
- maintainer error clustering：相同根因聚類 + 24h 去重，避免重複建任務
- lifecycle-orchestrator 分場景品質閾值：hook/automation 需 A 級，knowledge 需 B 級

**對應 rule**：`rules/常駐服務.md`（自動啟動、防呆、fallback）

### 3. 補全能力

📋 MUST 系統主動偵測缺口並建議補全。⛔ NEVER 只報告問題不建議行動。

**可檢驗標準**：
- 📋 MUST `/health` 含可操作的異常資訊（type + detail + severity）
- 📋 MUST 新增元件時檢查閉環完整性（closed-loop skill）
- ⚠️ SHOULD 功能完成時檢查 spec 歸檔完整性（nova-spec skill）

**現有實踐**：
- metrics 異常偵測：4 種 anomaly type，各有 severity 和 detail
- 元件閉環 checklist：4 層驗證（element-dependency、information-flow、spec-sync、review-checklist）
- nova-spec HARD-GATE：D1+ 功能必須通過 spec 審核
- Skill pruning：超過 MAX_SKILLS 時自動歸檔未引用的自動生成 skill（R10 phase transition 預防）
- 趨勢預警：hook error 趨勢上升但未達閾值時預先警告
- judge.js 方向性梯度：改善建議指出「加強哪個維度」，而非泛泛的「改善品質」

**對應 rule**：`rules/閉環規範.md`、`rules/知識管理.md`

## 規則關係

```
製作規則（how）        設計原則（what）
    ↓                      ↓
完全閉環  ←──────────→  禁止靜默失敗
自動修復  ←──────────→  常駐服務管理
補全能力  ←──────────→  元件閉環 + 知識持久化
```

## 合規 checklist

⛔ NEVER 新增元件未確認以下各項：

- [ ] 📋 MUST 有回饋路徑（完全閉環）
- [ ] 📋 MUST 有失敗恢復策略（自動修復）
- [ ] 📋 MUST 有缺口偵測機制（補全能力）
- [ ] ⛔ NEVER 自建平台已有能力（YAGNI）
- [ ] 📋 MUST 最小化狀態記錄（狀態最小化）
