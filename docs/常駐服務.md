# 常駐服務 — 章文件

> 最後更新：2026-03-17

## 概述

Nova Server 是 nova 唯一常駐 daemon，將 9 個獨立 hook 腳本整合為單一 HTTP 服務（port 3457）。同時承載 hook dispatch、Flow Visualizer UI、SSE 廣播、JSONL 持久化、模組熱重載。

## 架構圖

```
Claude Code
    ↓ stdin JSON
hook-client.js (PreToolUse Bash)
    ↓ HTTP POST /dispatch
server.js (port 3457, 常駐, 248 行)
    ├── handlerMap 路由（同步 dispatch）
    │   ├── guards.js        → PreToolUse:Bash, PreToolUse:Write, PreToolUse:Edit
    │   ├── flow-observer.js    → SessionStart, SessionEnd, UserPromptSubmit,
    │   │                        SubagentStop, PreToolUse:Agent, PostToolUse
    │   ├── context-injector.js → SessionStart（上下文聚合注入）
    │   ├── notification.js    → Notification
    │   └── metrics.js         → 可觀測層（subscriber，非 handler）
    ├── 結果聚合（block AND 語意）
    ├── event-bus.js（xstream 事件匯流排）
    │   ├── Daemon 模組（lifecycle，跨 dispatch 持久運行）
    │   │   ├── heartbeat     → 心跳 + session 控制
    │   │   └── self-drive    → 自我驅動閉環
    │   ├── Reactor 模組（SessionEnd 觸發）
    │   │   ├── maintainer    → 文件維護 + Notion + git
    │   │   ├── learner       → 行為偵測 + 信心追蹤
    │   │   └── judge         → 品質評分 + 趨勢
    │   └── 事件流
    │       ├── writeFlowEvent() → JSONL 持久化
    │       ├── pool.broadcast() → SSE 推送
    │       └── metrics.onEvent() → 計數 + 異常偵測
    └── Flow Visualizer 路由（/, /events, /api/*)
         ↓
    Flow Visualizer UI (http://localhost:3457)
```

### 模組間通訊原則

模組透過 event bus 溝通（`ctx.emit(eventType, payload)`），不互相 import。三種模組類型：

| 類型 | 說明 | 觸發時機 |
|------|------|---------|
| **Handler** | 同步 dispatch 處理（允許/阻擋決策） | 每次 hook 觸發 |
| **Daemon** | lifecycle 模組（長駐，跨 dispatch 運行） | server 啟動時 init |
| **Reactor** | SessionEnd 後觸發的背景 agent | SessionEnd 事件 |

統一模組介面：

```javascript
module.exports = {
  subscribe: ['EventType'],  // 監聽的事件（Daemon/Reactor）
  handler: { 'EventType': fn },  // 同步處理（Handler）
  init(ctx) { ... },  // 啟動時初始化（Daemon）
  destroy() { ... },  // 關閉時清理（Daemon）
};
```

## 模組介面

### Handler 格式

```javascript
module.exports = {
  on: {
    'EventType[:Matcher]': (input) => ({
      decision: 'allow' | 'block',
      reason?: string,
      events?: FlowEvent[],
    }),
  },
};
```

### Nova Server API

| 路徑 | 方法 | 說明 |
|------|------|------|
| `POST /dispatch` | POST | `{ eventType, matcher?, input }` → `{ decision, reason? }` |
| `GET /health` | GET | `{ status, uptime, modules, connections, metrics, anomalies }` |
| `POST /modules/reload` | POST | 重新載入模組 → `{ status, modules }` |
| `POST /agent/status` | POST | `{ name, status, detail? }` → 背景 agent 狀態回報 |

### 路由優先順序

1. **精確匹配**：`EventType:Matcher`（如 `PreToolUse:Bash`）
2. **| 展開**：`Write|Edit` → 分別查找 `PreToolUse:Write` 和 `PreToolUse:Edit`
3. **寬鬆匹配**：只用 `EventType`（如 `PostToolUse`）
4. **去重**：同一函式參考只執行一次

### 結果聚合

- **block AND 語意**：任一 handler 返回 block → 整體 block
- **events 合併**：所有 handler 的 events 陣列合併後寫入 JSONL + SSE

## Fallback 策略

hook-client.js 的 `fetch` 失敗時（nova-server 未啟動），自動 import 舊 hook 腳本的 `evaluate()` 函式。舊腳本保留不刪。

## 功能演進

### Nova Server（2026-03-14）

- **摘要**：單一常駐 HTTP daemon 取代 9 個獨立 hook process
- **關鍵決策**：
  - Port 3457 合併（取代舊 flow-server）
  - 模組隔離：dispatch 同步回傳 decision，事件推送 fire-and-forget
  - xstream event$ 統一事件管道（取代 watchFile 500ms 輪詢）

### Hook Client 防呆強化（2026-03-15）

- **摘要**：修正 hook-client.js 的身份驗證、日誌導向、stdin 效能
- **關鍵決策**：
  - `/health` 雙重驗證：`status === 'ok'` 且 `title === 'nova-server'`
  - spawn 日誌導向 `/tmp/nova-server.log`（`openSync` fd，禁止 ignore）
  - `Bun.stdin.text()` 取代手動 stream（0.1ms vs 1.6ms）
  - fetch 加 `AbortSignal.timeout(3000)` 防卡住

### 可觀測層（2026-03-15）

- **spec**：`archive/2026-03-15_nova-server-observability/spec.md`
- **摘要**：event$ 新增 metrics subscriber，`/health` 擴充 metrics + anomalies
- **關鍵決策**：
  - 不動 dispatch 核心（同步 for loop），只在 event$ 加 subscriber
  - 純記憶體滑動窗口（5 分鐘），重啟歸零
  - 4 種異常偵測：high_dispatch_rate、consecutive_blocks、handler_error_spike、memory_pressure

### 模組職責拆分（2026-03-16）

- **摘要**：flow-observer.js 拆分為純觀察（flow-observer）+ 純注入（context-injector）
- **關鍵決策**：
  - 觀察（寫出事件）和注入（讀入資料）是不同資料方向，不應混在同一模組
  - dispatch 的 fan-out 聚合機制讓拆分零成本 — 同一 handler key 多個 handler 自動合併
  - 新增 `rules/模組職責分離.md` 防止未來再混淆

### Statusline 服務狀態（2026-03-16）

- **摘要**：statusline 顯示 nova-server 和本地 LLM 的即時狀態
- **檔案**：`~/.claude/statusline.sh`
- **顯示格式**：`nova │ LLM │ Model │ Context%`
- **狀態**：
  - nova-server：🟢 `nova`（/health ok）、🔴 `nova ✗`（無回應）
  - 本地 LLM：🟢 `LLM`（連線正常）、🟡 `LLM ⏳`（推理中，有 lock file）、🔴 `LLM ✗`（斷線）
- **快取**：3 秒快取（`/tmp/nova-status-cache`），避免頻繁 curl
- **LLM 推理中偵測**：讀取 `/health` 的 `activeAgents`（背景 agent 回報），非 lock file

### Error Clustering + 自動修復任務（2026-03-17）

- **摘要**：maintainer Phase 3c 加入 error clustering 和 dedup，避免重複建立 Notion 修復任務
- **關鍵決策**：
  - 同 event+phase 的 hook error 聚為同一根因
  - 24h 內同一根因不重複建立 Notion 任務（`/tmp/hook-error-tasks-created.json` 去重）
  - 趨勢分析：7 天滑動窗口日計數 + 線性斜率，上升時簡報預警

### 趨勢分析預警（2026-03-17）

- **摘要**：maintainer generateBriefing 加入 hook error 趨勢預警和 Skill Library 健康度預警
- **關鍵決策**：
  - 7 天滑動窗口 + 線性斜率偵測趨勢方向
  - 斜率 > 0.5 且未達建任務閾值時 → 簡報預警（預測性自我修復，R9 研究啟發）
  - Skill Library 未引用 skill > 5 個時 → 預警可能的 phase transition

### Event-Bus 重構（2026-03-17）

- **摘要**：server.js 從命令式 setInterval + if-else 重構為 reactive xstream event bus
- **關鍵決策**：
  - server.js 507 → 248 行（-52%），職責縮減為純 HTTP + dispatch + 模組載入
  - 新增 event-bus.js 接管 Daemon/Reactor 生命週期管理
  - heartbeat 從 server 內嵌邏輯獨立為 Daemon lifecycle 模組
  - self-drive 從臨時 spawn 改為獨立 Daemon lifecycle 模組
  - 模組間零 import，透過 `ctx.emit` 溝通
  - 第一性原理：一切行為 = 事件 → 反應
