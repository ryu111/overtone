### 新增（Expert knowledge）

**1. 認知陷阱（替換校準嗅覺表格）**

3 個只有做過 50+ 次深度路由才會踩的陷阱：

- **錨定效應**：使用者說「小改動」→ agent 錨定 D0/D1，但改動影響 3 模組介面。解藥：忽略使用者複雜度描述，只看設計決策密度
- **沉沒成本**：D2 planner 花 5000 tokens 寫 spec 後，不願承認任務只需 D1。解藥：spec 完成後反問「沒有這份 spec，Main 能直接做嗎？」
- **並行幻覺**：5 個子任務就想 D4，忽略 3 個共享 config。解藥：先畫隱式依賴圖再決定

**2. 語言學信號（替換模糊任務降維法中的簡化版本）**

從任務描述的動詞和名詞推斷深度：

| 語言信號 | 深度暗示 | 因為 |
|---------|---------|------|
| 「加一個 X」「改 Y 為 Z」 | D0/D1 | 操作已明確 |
| 「我們需要 X 能力」「讓系統支援 Y」 | D2 | 意味著設計空間 |
| 「重新思考 X」「X 架構有問題」 | D2/D3 | 推翻既有設計 |
| 「做一個 X」（名詞是系統/平台） | D3/D4 | 全新 = 大量設計決策 |

**3. 情境路由表（新增段落）**

| 你的情境 | 載入哪個 reference | 第一步 |
|---------|-------------------|--------|
| 不確定 D1 還是 D2 | boundary-cases.md | 找最相似案例 |
| 決定了深度，要委派 | delegation-quality.md | 檢查委派品質信號 |
| D4 拆分怕隱式依賴 | implicit-dependencies.md | 跑 5 類分類法 |

**4. 判斷流程快速路徑（新增段落）**

```
任務進來 → 核心兩問(2s) → 語言信號(3s) → 決策密度(10s) → 可逆性(5s) → 成本合理性(5s) → 最終深度
```
